# 추천 코스 서비스 기획 및 백엔드 개발 범위

> 회의 목적: 서비스 전체 흐름을 함께 확인하고, 백엔드에서 구현할 기능과 미정 정책을 정리한다.
>
> 문서 상태: 회의 전 검토 초안
>
> 작성일: 2026-08-21

---

## 1. 회의에서 먼저 확인할 것

먼저 아래 서비스 흐름이 전체 기획 의도와 맞는지 확인한다.

```text
사용자 입력
→ 대표 코스 여러 개 추천
→ 코스 선택
→ 코스 상세 수정
```

대표 코스가 마음에 들지 않으면 다음 흐름으로 이동한다.

```text
다른 코스 탐색
또는
직접 코스 생성
```

이 문서의 백엔드 기능 목록은 위 흐름을 기준으로 작성한 초안이며, 회의에서 기획과 다른 부분을 수정한다.

---

## 2. 서비스가 해결하려는 문제

사용자가 외출·데이트 코스를 만들 때 지역, 장소, 식당, 카페를 직접 검색하고 순서를 조합해야 하는 번거로움을 줄인다.

사용자는 간단한 정보를 입력하고, 서비스는 조건에 맞는 대표 코스를 여러 개 제안한다. 사용자는 코스를 그대로 이용하거나, 필요한 부분만 수정할 수 있다.

처음부터 장소를 직접 골라 코스를 만들고 싶은 사용자를 위해 직접 코스 생성 흐름도 제공한다.

---

## 3. 주요 용어

| 용어 | 의미 | 예시 |
|---|---|---|
| City | 서울·대전처럼 큰 도시 | 서울 |
| Area | 도시 안의 세부 지역 | 성수, 용산, 여의도 |
| Place | 서비스가 수집·관리하는 모든 장소 | 식당, 카페, 전시관 |
| Anchor | 코스의 시작점이 되는 실제 장소 | 더현대, 아이파크몰, 한강공원 |
| Course | 앵커와 주변 장소를 연결한 일정 | 앵커 → 식당 → 카페 |

Area는 앵커나 코스가 아니다. 서울처럼 범위가 큰 City에서 추천 범위를 줄이기 위한 탐색 단위다.

---

## 4. 사용자 입력

사용자는 다음 정보를 입력한다.

| 입력 | 내용 |
|---|---|
| 지역 | City, Area 또는 특정 장소 |
| 시간 | 정확한 시간 또는 시간대 |
| 누구와 | 가족, 친구, 연인 등 |
| 무엇을 | 활동·음식·분위기 키워드 복수 선택 |

### 키워드 정책

화면에서는 여러 선택지를 제공할 수 있지만, 유사한 선택지는 추천 계산 시 하나의 대표 태그로 통합한다.

```text
전시 / 전시 관람 / 갤러리 / 미술관·박물관
→ 대표 태그: EXHIBITION
```

현재 코드에서는 `TagCode`가 대표 태그와 화면 선택지 목록을 함께 관리한다. 키워드 목록은 아직 최종 확정 전이다.

---

## 5. 대표 코스 추천 흐름

```text
사용자 입력
→ 대표 코스 후보 생성
→ 대표 코스 여러 개 노출
→ 코스 선택
→ 코스 상세 화면
```

대표 코스는 고정된 상품이 아니라 사용자 입력과 최신 장소 데이터를 바탕으로 생성되는 추천 후보로 본다.

예시:

- 용산 쇼핑·팝업 코스
- 성수 전시·카페 코스
- 여의도 한강·식사 코스

대표 코스가 마음에 들지 않으면 다른 대표 코스를 다시 탐색할 수 있다.

### 회의 결정 필요

- 대표 코스를 몇 개 노출할지
- 대표 코스의 제목과 추천 이유를 어떻게 보여줄지
- 대표 코스를 언제 다시 생성할지
- 대표 코스 선택 직후 편집할지

---

## 6. 코스 상세 및 편집

선택한 코스는 세로형 스케줄 표로 보여준다.

기본 일정 예시:

```text
앵커 → 활동 → 식사 → 카페
```

사용자는 다음을 수정할 수 있다.

- 일정 순서 변경
- 장소 교체
- 일정 삭제
- 일정 앞·뒤에 새 일정 추가
- 활동·식사·카페 유형 변경

장소를 추가하거나 교체할 때는 직전 장소를 기준으로 다시 추천한다.

```text
앵커 → A카페 → B식당 → C활동
```

중간에 장소를 추가하면 이후 추천 기준도 바뀐다.

```text
앵커 → A카페 → D전시 → B식당 → C활동
```

이후 B식당은 A카페가 아니라 새로 추가된 D전시 주변을 기준으로 추천한다.

### 회의 결정 필요

- 기본 일정 폼을 시간대별로 어떻게 구성할지
- 추천 완료 후에만 편집할지, 추천 중에도 편집할지
- 일정 사이 추가 시 직전 장소만 볼지, 앞·뒤 동선을 함께 볼지

---

## 7. 앵커 정책

모든 코스에는 앵커가 하나 존재한다.

```text
앵커
→ 주변 활동 추천
→ 활동 장소 선택
→ 선택한 장소 주변 식당 추천
→ 식당 선택
→ 선택한 장소 주변 카페 추천
```

앵커는 실제 좌표가 있는 `Place`다. 앵커 후보로 관리되지 않는 장소라도 사용자가 직접 선택하면 이번 코스의 앵커가 될 수 있다.

---

## 8. 직접 코스 생성

대표 코스를 선택하지 않고 사용자가 처음부터 코스를 만드는 흐름이다.

현재 후보는 두 가지다.

### 방식 A

```text
서울 → Area → 앵커
```

서울처럼 큰 도시를 입력하면 키워드에 맞는 Area를 먼저 추천하고, 사용자가 Area를 선택한 뒤 해당 Area의 앵커를 고른다.

### 방식 B

```text
서울 → 앵커
```

Area 선택을 생략하고 서울 범위 안의 앵커를 바로 탐색하거나 추천한다.

특정 장소를 직접 입력하는 경우도 이 흐름에 포함한다.

```text
서울 → 더현대 직접 입력 → 더현대가 앵커
```

### 현재 미정

직접 코스 생성에서 Area를 항상 거칠지, City에서 바로 앵커를 찾을지 아직 결정하지 않는다.

---

## 9. 장소 데이터 흐름

추천은 외부 API 응답을 즉시 사용하지 않고, 정제된 내부 DB의 장소를 대상으로 한다.

```text
외부 API 수집
→ 중복 제거
→ 주소·좌표 정제
→ ACTIVITY / FOOD / CAFE 분류
→ 태그 부여
→ Place DB 저장
→ 추천에 활용
```

장소 운영 데이터에는 다음이 포함된다.

- 외부 제공자와 외부 장소 ID
- 소속 Area
- 장소 유형
- 이름·주소·좌표·전화번호
- 운영시간·운영요일
- 앵커 후보 여부
- 활성 여부
- 사용자 선택 횟수
- 마지막 선택 시각
- 마지막 외부 동기화 시각

카카오 장소 ID만으로 단건 상세 동기화하는 API는 제공되지 않으므로, 오래된 장소는 저장된 이름·주소·좌표를 이용해 재검색한다.

---

## 10. 태그 및 추천 데이터

태그는 하나의 공통 사전을 사용한다.

```text
Tag
├─ AreaTag
└─ PlaceTag
```

- `Tag`: 대표 키워드
- `AreaTag`: 해당 Area가 어떤 경험에 적합한지 표현
- `PlaceTag`: 해당 Place가 어떤 활동·음식·분위기에 적합한지 표현
- `weight`: 해당 태그가 Area 또는 Place를 대표하는 정도

예시:

```text
용산
- 쇼핑: 90
- 팝업: 80
- 전시: 60

아이파크몰
- 쇼핑: 100
- 실내: 90
- 팝업: 70
```

## 11. 백엔드 구현 기능 초안

### 11.1 장소 수집·관리

- 카카오 API 장소 수집
- 수집 데이터 정제 및 분류
- City·Area 연결
- 외부 장소 ID 기반 중복 처리
- 장소 저장 및 갱신
- 장소 활성·비활성 관리
- 오래된 장소 재동기화
- 장소 선택 횟수 기록

### 11.2 지역·태그 관리

- City 목록 조회
- City의 Area 목록 조회
- TagCode 및 태그 데이터 관리
- AreaTag·PlaceTag 연결
- Area별 태그 조회
- Place별 태그 조회
- 키워드 기반 Area 점수 계산

### 11.3 앵커 추천

- Area 내 앵커 후보 조회
- 사용자 키워드 기반 앵커 점수 계산
- 앵커 후보 정렬
- 특정 Place 직접 검색
- 직접 선택한 Place를 앵커로 확정

### 11.4 대표 코스 추천

- 사용자 입력 검증
- 대표 코스 후보 생성
- 대표 코스 여러 개 반환
- 다른 코스 재탐색
- 선택한 대표 코스를 Draft로 변환

### 11.5 코스 편집

- 일정 추가
- 일정 삭제
- 일정 순서 변경
- 장소 교체
- 직전 장소 기준 재추천
- 수정된 Draft 반환

### 11.6 코스 저장

- Draft 코스 저장
- 저장된 코스 조회
- 저장된 코스 수정
- 코스 삭제 또는 보관

---

## 12. 권장 구현 순서

```text
1. 장소 수집·저장
2. City·Area·Tag 데이터 구성
3. Area 조회 및 추천
4. 앵커 조회 및 선택
5. 앵커 기준 장소 추천
6. 대표 코스 생성
7. 코스 편집
8. 코스 저장
9. 직접 코스 생성
```

직접 코스 생성의 상세 흐름은 대표 코스 추천 구조를 확인한 뒤 결정한다.

## 13. 회의에서 결정할 항목

- 전체 사용자 흐름이 기획 의도와 일치하는가
- 대표 코스의 정의와 생성 기준
- 대표 코스 노출 개수
- 대표 코스 재탐색 방식
- 직접 코스 생성 방식: `City → Area → Anchor` 또는 `City → Anchor`
- 시간 입력 방식
- 시간대별 기본 일정 폼
- 추천 중 편집 가능 여부
- 코스 저장 기능의 초기 포함 여부
- 키워드 목록과 유사 키워드 통합 기준
- Area 추천을 초기 버전에 포함할지
