# 장소 수집 스케줄링 구현 현황

갱신: 2026-11-16

사용자가 직접 작성하는 방식에서 **AI가 구현하고 구조·동작을 설명하는 방식**으로 변경했다.
기존 pipeline/scheduler 구성은 삭제하고 정책 기반 scheduling 패키지로 재구성했다.

현재 구조·설정·오류 처리·확인 방법은 [스케줄링 가이드](./scheduling-guide.md)가 기준이다.

## 확정 방향

- INIT 정책으로 서울 Area ID순 초기 수집.
- 매일 03:00 KST부터 실행, 예산 소진까지 진행. AI 결과 회수는 별도 지속.
- 카카오·네이버 각각 독립 쿼터의 main/team 인증 정보, 소진 응답 시 다음 키 전환.
- 네이버 API HUB는 지역/블로그 공통 검색 월간 한도 기준.
- 정확한 사용량 카운터를 만들지 않고 키별 대기 상태를 DB에 저장.
- 기존 Job/Temp 이력 활용, 미완료 카카오 구역은 첫 페이지부터 재검색.
- 초기 회차·대상 테이블과 페이지 체크포인트는 보류.
- 운영 정책은 인터페이스 교체로 추후 구현. 신규/변경/동일/폐업 판정의 세부 정책은 추후 결정.

## 구현

- [x] 전용 스레드 4개와 4개 scheduler
- [x] readiness와 단일 인스턴스 복구
- [x] 미등록 Area 선정과 원자적 중복 방지 등록
- [x] 키별 scope 대기 상태 저장과 main/team 전환
- [x] 카카오/네이버 정상 대기 및 재개
- [x] AI 제출 상한·quota 대기·독립 결과 회수
- [x] 단계별 대기량 상한
- [x] 기존 호출부/환경 설정/테스트 갱신
- [x] 격리 DB와 모의 HTTP 검증
- [ ] 실제 계정 키 입력 및 모델명 확인
- [ ] 테스트 데이터 초기화 범위 확인·실행

이번 구현은 데이터를 삭제하거나 자동 실수집을 시작하지 않는다. 자동 실행 기본값은 OFF다.


## pipeline 후속 정리 완료

수동 테스트 Controller/Orchestrator/즉시 AI 경로와 전용 DTO를 제거했다. 카카오 Job 등록은 등록 서비스로 모았고, AI 최종 Writer는 하나로 통합했다. 복구는 scheduling/service/CollectionRestartRecovery로 이동했다. 최신 파일별 역할과 검증 결과는 scheduling-guide.md 8절을 따른다.
